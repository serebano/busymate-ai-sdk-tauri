Busymate AI SDK for Tauri

Busymate AI hosted chat in its own Tauri v2 webview window, with the identity bridge answered from your app's Rust side and a tap-triggered microphone adapter.

What it does

tauri-plugin-busymate-ai (Rust) plus tauri-plugin-busymate-ai-api (JavaScript bindings). The plugin opens the hosted chat in its own webview window, answers busymate.bridge/2 from Rust, and asks the OS for the microphone only when the user taps the chat's microphone or voice control, on macOS (AVFoundation), Windows (privacy consent switches) and Linux. Runtime IPC is scoped to the chat window and its exact origins.

Chat in its own window

open_chat loads your tenant's chat URL on channel=desktop_sdk: a top-level page with the normal chat layout and locale applied from the first frame.

Identity from Rust

Your account and mint callbacks run in the Rust side of your app; the plugin grants the bridge and microphone commands only to the chat window at runtime.

Microphone through Tauri

WebView2, WKWebView and WebKitGTK media decisions go through Tauri's on_permission_request; renderer recovery sends restored.

Example app

example-app/ is a real Tauri app that consumes the plugin and its JS bindings, with a settings view and a callbacks log.

Install

Nothing is published to crates.io or npm; depend on the tagged source or the release files.

  1. Add the plugin to src-tauri/Cargo.toml at the 1.0.1 tag (or extract tauri-plugin-busymate-ai-1.0.1.crate from the release and use path).

    [dependencies]
tauri-plugin-busymate-ai = { git = "https://github.com/serebano/busymate-ai-sdk-tauri", tag = "1.0.1" }

  2. Optional JavaScript bindings for opening the chat from your frontend.

    npm install ./tauri-plugin-busymate-ai-api-1.0.1.tgz @tauri-apps/api

  3. Register the plugin with your account, mint and on_close callbacks, add .on_permission_request(tauri_plugin_busymate_ai::permission_handler), then call app.busymate_ai().open_chat(ChatOptions { .. }). Add busymate-ai:default to your local window's capability only if your frontend calls the bindings.

Identity linking and the microphone

Both bridges are installed by your app before the chat's first load. Your native app release is what installs or upgrades native SDK code; the hosted chat updates independently.

Identity linking

The plugin answers busymate.bridge/2 (wire v2, build 2.0.0) from your app's Rust side: your signed-in account id (only SHA-256 of appId:id reaches the chat) and a fresh single-use assertion minted by your authenticated backend on every call. Read identity.md.

Microphone

The microphone adapter (wire 1, adapter 1.0.0) asks the OS only on the user's tap and forwards the webview's own media decision through Tauri's permission hook. On macOS add NSMicrophoneUsageDescription to src-tauri/Info.plist. Read microphone.md.
